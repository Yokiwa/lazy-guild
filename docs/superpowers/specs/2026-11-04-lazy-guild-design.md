# 懒人公会 / Lazy Guild — 设计文档

- 日期：2026-11-04
- 状态：待审阅
- 仓库：`Yokiwa/lazy-guild`（公开）

## 1. 目标与背景

**一句话**：给"从来不按计划执行，但又想有个计划"的人用的计划 App。到点只让你从 2–3 件事里挑一件，用冒险者公会的游戏外壳让人愿意每天打开。

**用户**：先给我自己用（iPhone），以后公开给别人用，放进简历和作品集。赚到钱以后再考虑做成正式产品（不在本期范围）。

**要解决的两个问题**（我自己的计划就是这样失败的）：

1. **计划太满** → 一落后就全盘放弃。对策：每个时间点只做一件事；没做的事不堆成逾期；永远没有惩罚。
2. **不想开始** → 拖延。对策：到点不用自己决定，只做二选一 / 三选一；15 分钟内接取有额外奖励。

**成功的标准**：

- 到点手机弹通知 → 点开就是选择卡片 → 选一个就开始，全程不超过 3 次点击
- 委托时长到了再弹通知问"完成了吗"
- 完成、部分完成都有奖励，没做什么都不扣；一个月后还愿意打开
- 公开仓库能直接放进作品集：双语 README、截图、测试、自动部署齐全

## 2. 范围

**包含**：PWA 网页 App（中英双语）、游戏系统（公会 + 伙伴）、Cloudflare 推送服务、本地数据与备份、测试、CI/CD、部署文档。

**不包含（YAGNI）**：账号注册与云端同步；多设备共享数据；社交 / 排行榜；应用商店上架；付费；AI 自动排计划；截止日倒排（课程作业以普通委托的形式放进时段即可）。

## 3. 核心概念

| 概念 | 说明 |
|---|---|
| **委托模板**（Quest） | 想做的一件事。字段：名称、类型（力量 STR / 智力 INT / 技艺 SKL）、默认时长（5 分钟–8 小时）、图标 |
| **委托时段**（Slot） | 一周中某几天的某个时间（如周一、三、五 19:00），挂 2–3 个候选委托模板。每天最多 6 个时段 |
| **时段场次**（Slot occurrence） | 某个时段在某一天的一次出现，例如"2026-11-09 周一 19:00"。由时段推算出来，不单独存储 |
| **冒险**（Run） | 接下的一次委托。状态：`active` → `done` / `partial` / `skipped` / `abandoned` |
| **冒险者**（Profile） | 名字、等级、经验、金币、三项属性、伙伴、装扮、徽章、休息券 |

## 4. 核心循环与页面

### 4.1 一次完整的循环

1. 时段到点 → 推送"⚔️ 新的委托到了！"
2. 点通知 → 打开 App 的**选择卡片**，列出该时段的 2–3 个候选委托，点一个即接取
3. 进入**冒险中**：倒计时 + 伙伴陪伴；可以"提前完成"或"放弃"
4. 时长到 → 推送"委托完成了吗？" → 点开进入**结算**：完成 / 做了一部分 / 没做
5. 结算画面：经验、金币、属性、可能的升级 / 进化，伙伴说一句话

### 4.2 场次的有效期

- 一个场次从时段时间开始可以选，**到当天下一个时段开始或当天 24:00（以先到者为准）** 为止
- 过期的场次安静消失，不记录、不惩罚
- 首页随时可以"现在就接个委托"（自由委托），不依赖通知

### 4.3 页面

1. **公会大厅（首页）**：伙伴、等级与阶级、进行中的委托、今天的时段、连续冒险天数、休息券数量
2. **委托选择卡**：到点时的二选一 / 三选一；自由委托也用这个页面（从全部模板里挑）
3. **每周计划**：七天视图，增删改时段
4. **委托库**：管理委托模板；首次打开预置示例（健身、学习一小时、写作业、推进项目）
5. **冒险者档案**：属性面板、徽章、冒险日志。**日志只列做了什么**（完成和部分完成），不列没做的
6. **设置**：语言、通知开关与同步状态、导出 / 导入备份、关于
7. **公会商店**：用金币买装扮、背景、称号、休息券（从首页进入）

### 4.4 第一次打开

起名字 → 选伙伴 → 引导"添加到主屏幕"并开启通知（可跳过）→ 创建第一个时段。

## 5. 游戏系统

所有数字集中在 `packages/core/src/balance.ts`，调整数值只改这一个文件。

### 5.1 奖励

- 计入时长 `m` = min(计划时长, 180) 分钟
- **经验** = max(10, round(m / 60 × 30))
- **金币** = floor(经验 / 2)
- **属性**：对应类型 +floor(m / 30)，至少 +1
- **部分完成**：经验、金币、属性全部减半（向下取整，经验至少 5）
- **没做 / 放弃**：全部为 0，不扣任何东西
- **迅速接取 +20%**：从通知对应场次开始 15 分钟内接取，经验和金币 ×1.2（向下取整）；自由委托没有这个加成
- 提前完成按计划时长结算（不是实际用时）—— 不让人因为提前完成而吃亏

### 5.2 等级与阶级

- 从等级 L 升到 L+1 需要 `100 + 20 × (L − 1)` 经验；满级 50
- 阶级：F 1–4、E 5–9、D 10–14、C 15–24、B 25–34、A 35–49、S 50

### 5.3 连续冒险天数与休息券

- 某天至少有一个 `done` 或 `partial` 的冒险（按**开始日期**算）→ 这天算"冒险日"
- 每周一 00:00 发 2 张休息券，持有上限 3 张；商店可买，同样受上限限制
- 某天不是冒险日 → 自动消耗 1 张券，连续天数不断；没有券 → 连续天数归零
- 连续天数和券的消耗**每次都从冒险日志重新推算**（纯函数），所以第二天才确认昨天的冒险也能得到正确结果
- 当天还没结束时不算"空白日"
- 里程碑 3 / 7 / 14 / 30 / 100 天：分别奖励 20 / 50 / 100 / 200 / 500 金币和一枚徽章（每个里程碑只发一次）

### 5.4 伙伴

- 开局三选一（原创）：**史莱姆**、**狐火精灵**、**幼龙**
- 形态：幼年（F–E）、成长期（D–B）、完全体（A–S）；跨形态时播放进化动画
- 台词场合：打招呼、接取、完成、部分完成、没做、升级、进化、使用休息券；每种场合每个伙伴至少 3 句，中英双语，随机出
- 没有心情值，不会受伤、生病或离开

### 5.5 公会商店

- 商品类型：伙伴装扮（帽子 / 披风等）、大厅背景、称号、休息券
- 每件商品有价格和最低阶级要求；升阶时提示"解锁了新商品"
- 首版至少 12 件商品（不含休息券）

### 5.6 徽章

首版约 12 枚，例如：第一次完成委托、第一次部分完成、力量 / 智力 / 技艺分别累计 50 点、连续 7 / 30 天、一周内完成三种类型、第一次用休息券、升到 C 阶、升到 S 阶、迅速接取 10 次。

### 5.7 美术

伙伴（3 种 × 3 形态）、背景、装扮都用原创 SVG，风格简洁可爱。图片集中在 `apps/web/src/assets/`，可直接替换。不使用任何现有动漫作品的角色或画风。

## 6. 架构

### 6.1 仓库结构（pnpm workspace，TypeScript）

```
lazy-guild/
├── packages/core/        纯逻辑：奖励、升级、阶级、连续天数、场次推算、数据校验。无 DOM、无网络
├── apps/web/             React + Vite + vite-plugin-pwa；Dexie（IndexedDB）；中英 i18n
├── apps/push-worker/     Cloudflare Worker + D1 + Cron Trigger（每分钟）
├── docs/                 设计、计划、部署与 iPhone 使用指南
└── .github/workflows/    CI 和部署
```

### 6.2 数据存放

**手机本地（IndexedDB，唯一的真实数据）**：profile、quests、slots、runs、purchases、settings。数据库带版本号，结构变化时自动迁移。

**推送服务（D1）**：只存
- `devices`：设备 id、密钥哈希、推送订阅（endpoint 与密钥）、IANA 时区、语言
- `slot_times`：设备 id、时段 id、星期几、时间（HH:mm）
- `one_offs`：设备 id、提醒 id、UTC 时间、类型（目前只有"完成确认"）
- `sent_log`：设备 id + 场次键，用于防重复

**不存**委托名称或任何游戏数据。通知文字是按语言选的通用句子。

### 6.3 推送服务接口

所有接口（除注册外）需要请求头 `Authorization: Bearer <设备密钥>`。

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/devices` | 注册：提交推送订阅、时区、语言 → 返回设备 id 与密钥 |
| PUT | `/devices/:id` | 更新订阅、时区、语言 |
| DELETE | `/devices/:id` | 注销，删掉这台设备的全部数据 |
| PUT | `/devices/:id/slots` | 整体替换这台设备的时段时间表 |
| PUT | `/devices/:id/one-offs/:oid` | 新建或更新一次性提醒（冒险结束确认） |
| DELETE | `/devices/:id/one-offs/:oid` | 取消一次性提醒 |
| GET | `/vapid-public-key` | 返回 VAPID 公钥 |

**每分钟的定时任务**：对每台设备，用它的时区算出当前星期和时分 → 找到匹配的时段 → 场次键（时段 id + 本地日期）不在 `sent_log` 里才发送；到期的一次性提醒发送后删除。推送服务返回 404 / 410 时删除该设备。Web Push 加密用 WebCrypto 实现（Workers 环境下可用的库或自写），VAPID 私钥放 Worker 密钥里。

### 6.4 手机端的推送处理

- Service Worker 收到推送 → 显示通知，数据里带目标路径（`/choose?slot=<id>&date=<日期>` 或 `/confirm?run=<id>`）
- 点击通知 → 打开或切到 App 的对应页面
- 启动时检查订阅是否还有效，失效就重新注册；检测到时区变化就同步

### 6.5 同步

- 时段改动、接取或结束冒险时，把对应的推送请求放进本地"待同步队列"，在线时立即发送，失败的话下次启动或恢复联网时重试
- 设置页显示通知状态：已同步 / 待同步 / 未开启 / 不支持（附原因）
- 没有配置推送服务地址时（本地开发、没配 Cloudflare），App 完整可用，只是通知显示"未配置"

### 6.6 备份

- 导出：全部本地数据 → 一个带版本号的 JSON 文件
- 导入：先校验整份文件，任何错误都整份拒收；通过后先自动导出一份当前数据，再替换
- 超过 30 天没导出时，首页提醒一次（可关闭）

## 7. 边界情况

| 情况 | 处理 |
|---|---|
| 有进行中的委托时又到了新场次 | 同时只能有一个进行中的委托。选择卡片提示"先把当前的做完"或"放弃当前的，接新的" |
| 冒险中关了 App / 手机没电 | 结束时间存在本地；下次打开发现已过时间，直接进入结算 |
| 隔天才确认 | 奖励照发，算在开始那天；连续天数重新推算 |
| 没开通知 / 拒绝权限 / 没添加到主屏幕 | App 照常可用；首页提示如何开启 |
| 订阅失效 | 服务端删除设备；App 下次启动时重新注册 |
| 重复推送 | `sent_log` 保证每个场次只发一次 |
| 换时区 | App 检测后同步，服务端按新时区计算 |
| 备份文件损坏 | 整份拒收，提示原因，不做部分导入 |
| 重复结算 | 冒险只能从 `active` 转出一次，之后的结算请求忽略 |
| 夏令时切换 | 服务端用 IANA 时区计算本地时间；跳过的时刻（如 2:30 不存在）当天不发，重复的时刻只发一次 |
| 输入越界 | 时长 5–480 分钟、每时段 2–3 个候选、每天最多 6 个时段，表单直接限制 |

## 8. 测试

- **core（Vitest 单元测试）**：三种结算的奖励、180 分钟上限、迅速接取加成、各阶级门槛、升多级、连续天数加休息券（含晚确认、券上限、周一发券）、里程碑只发一次、场次有效期、夏令时、备份校验
- **push-worker（Vitest + Workers 测试环境）**：每个接口、密钥验证、定时任务的匹配逻辑、防重复、404 / 410 清理、时区与夏令时；真实推送用替身
- **web**：关键组件测试；Playwright 端到端测试，用假时钟走完整流程：首次打开 → 建时段 → 快进到 19:00 → 选委托 → 快进 2 小时 → 确认完成 → 升级、伙伴说话；另测离线使用、中英切换、导出导入、iPhone 屏幕尺寸
- **CI（GitHub Actions）**：每次推送跑 lint、类型检查、全部测试；main 分支全部通过后自动部署（需要仓库里配置 Cloudflare 密钥，没配就跳过部署）
